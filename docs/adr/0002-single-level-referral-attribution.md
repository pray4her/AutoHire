# 专家推荐裂变:单级归因、ops 生成与发送、当场归因

> **已被 [ADR-0003](./0003-referrer-email-referral-apply-shell.md) 取代**（就「挂本系统 Expert、介绍落地页、展示字段、档案内生成台」而言）。仍有效且被 0003 继承的部分：单级裂变、不透明 token、线下发送、当场归因、每归属方单 ACTIVE、不做多级/长效 cookie/系统发信。

新增推荐功能:ops 在专家档案后台为某专家生成推荐链接并线下发送给专家,专家转发给朋友;朋友点开链接无需登录即可查看专家公开信息(ops 生成链接时自选展示字段,目录为姓名/头衔/机构/邮箱/电话,联系方式默认不勾选),点击"开始申报"进入注册(走账号轨),注册完成即建立推荐归因。

关键决策:**单级裂变**——朋友注册后不会自动获得自己的推荐 token;"朋友其实也是专家"的正当场景由 ops 手动为其生成链接覆盖,资格控制权留在 ops。**推荐 token 为不透明随机串**,数据库映射到专家,只存哈希;邮箱绝不编码进 token(链接会被任意转发,编码邮箱等于广播 PII,且不可撤销、无法做点击分析)。token 带过期时间(默认 90 天,ops 可续期/重发),过期链接展示专门的失效落地页。**归因仅在当场建立**:点链接→同一会话内注册完成才绑定;事后从首页直接注册的不补归因,不上长效 cookie(last-click 争议规则的成本超过收益,丢失的只是归因数据而非申报)。

## Considered Options

- **多级裂变(朋友自动获得推荐 token,树状归因)**:申报者构成会脱离 ops 质量控制,且需处理推荐路径、层级贡献、循环归因,与专家定向招募的业务本质不符,被否。
- **邮箱派生/编码 token**:PII 泄漏、不可撤销、无法追踪点击,被否。
- **系统自动生成并邮件发送推荐链接给专家**:专家邮箱数据不可靠(仅来自简历解析,且流程后期才存在),被否(v1 采用 ops 手动生成+线下发送;专家自助复制页留作后续增强)。
- **30 天长效 cookie 归因窗口 / 注册时手填推荐人邮箱**:归因规则复杂或体验差,被否;若上线后归因丢失反馈多,再增量加 cookie 窗口。
- **每专家多个 token(渠道归因)**:实际只有"专家个人转发"一种渠道,属投机性设计,被否(每专家一个 token)。

## Consequences

- 申报表新增推荐归因外键(单值,非路径),归因数据可供 ops 在专家档案查看转化漏斗;点击日志复用 InviteAccessLog 同款模式。
- 推荐落地页公开展示专家信息,ops 生成链接时需知情(界面提示)。
- 推荐 token 状态机为 ACTIVE / DISABLED + expiredAt,复用邀请 token 的心智模型。
- v1 不做:专家查看自己推荐效果的面板、朋友注册时的通知邮件。
